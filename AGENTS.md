## Code-Stil
- TypeScript Strict Mode verwenden
- Funktionale Komponenten in React bevorzugen
- ESLint- und Prettier-Konfigurationen verwenden
- Conventional Commit Format befolgen
- jede erstellte Methode / funktion (egal ob in typescript oder c#) muss mit einem enstrechendem doc comment versehen werden
- für jedes Frontend (Admin und Vault) sollen ausschließlich shadcn/ui Komponenten verwendet werden, Nur wenn es keine passende Komponente von shadcn/ui gibt, dürfen andere UI-Komponenten erstellt werden

## Entwicklungs-Workflow
- jede Änderung muss in CHANGELOG.md gemäss den Richtlinien von https://keepachangelog.com/en/1.1.0/ dokumentiert werden
- Neue Pläne müssen in docs/plans/open angelegt werden. Niemals ausserhalb des Repositories!
- Fertige Pläne müssen nach docs/plans/closed verschoben werden
